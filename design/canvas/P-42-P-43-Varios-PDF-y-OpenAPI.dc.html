P-42

Un PDF por plantilla o por juego de datos

Desde la 0.16, «Exportar → PDF…» genera un PDF de verdad con el motor nativo, pero de uno en uno. Quien tiene siete plantillas, o una factura con doce clientes de ejemplo, repite el diálogo siete o doce veces. «Varios PDF…» los genera todos de una vez: un PDF por plantilla, o un PDF de la misma plantilla por cada juego de datos. Usa el mismo motor que «PDF…», así que solo existe en la app de escritorio; en la web el menú no cambia.
Propuesta 0.17 · solo escritorio · pendiente de visto bueno
1 · Menú Exportar (escritorio)
Justo debajo de «PDF…». En la web no aparece (allí no hay motor nativo).
2 · Un PDF por plantilla
Exportar varios PDF
Cada plantilla que es una página se genera con los datos actuales («Clínica Aurora»). Los parciales no se exportan.
linkpartials/cabecera.pug parcial, no se exporta
3 · Un PDF por juego de datos
Exportar varios PDF
La misma plantilla, una vez por cada juego de datos elegido. El nombre del juego va en el nombre del archivo.

picture_as_pdf
Generando presupuesto.pdf · 2 de 4
Se generan de uno en uno. «Cancelar» detiene el que está en curso y deja en la carpeta los ya terminados (se dice cuáles).

P-43

Datos de ejemplo desde una operación de OpenAPI

Hoy «Importar JSON, Schema u OpenAPI…» convierte un OpenAPI en un juego de datos con una clave por cada esquema del documento (cita, paciente, factura…), que casi nunca coincide con lo que recibe la plantilla. Lo que la plantilla recibe es la respuesta de una operación: GET /facturas/{id}. Al importar un OpenAPI se elige la operación y su respuesta, y el juego de datos sale con esa forma exacta. No se llama a la API: solo se lee el archivo que eliges, como hasta ahora. Web y escritorio.
Propuesta 0.17 · pendiente de visto bueno
1 · Se entra por donde siempre
Menú «⋯» de la zona de Datos (sin cambios). Con un JSON o un JSON Schema no cambia nada: se importa directo. Solo un OpenAPI abre el diálogo.
2 · Elegir la operación
Importar de OpenAPI · clinica-api.yaml
API de Clínica Aurora 2.3 · 14 operaciones · 9 esquemas. Solo se lee este archivo: no se llama a la API.

A la derecha del diálogo, se actualiza al cambiar de operación o de respuesta. Las claves que usa la plantilla abierta y no están en la respuesta se avisan: «La plantilla usa cliente.email, que esta respuesta no trae».
4 · «Valores»
check_circle
Ejemplos del documento
Si la respuesta o el esquema traen example / examples, se usan tal cual. Es lo más parecido a la API real.
check_circle
Generados
Datos inventados con el generador de siempre (nombres, fechas, importes), según tipo y formato. Es lo que hay si el documento no trae ejemplos.
check_circle
Las listas, con 3 elementos
Como en el resto de los datos de ejemplo; después se editan en la tabla.
5 · Operaciones que no sirven
Se listan apagadas y con el motivo, para que no parezca que faltan. Si una operación tiene varias respuestas (200, 404) se propone la primera 2xx con JSON.
6 · Al importar

El juego nuevo queda activo y se puede deshacer, como cualquier importación.
7 · Archivos .yaml
check_circle
Se aceptan .json, .yaml y .yml
Casi todos los OpenAPI se escriben en YAML; hoy solo se lee JSON y hay que convertirlos fuera.
warning
Referencias a otros archivos
Un $ref a otro archivo (./paciente.yaml) no se sigue: se avisa y esa parte sale vacía. Las referencias dentro del mismo documento sí.
8 · Si el documento no tiene operaciones
info
Este OpenAPI no declara operaciones (paths). Se importan sus 9 esquemas, como hasta ahora.
«Importar todos los esquemas» sigue disponible siempre en el diálogo: es el comportamiento de hoy.
